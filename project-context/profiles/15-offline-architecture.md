## 1. Overview
The app is designed with a robust offline-first architecture using local caching, optimistic mutations, debounced upload coalescing, and serialized background synchronization to Google Drive Excel spreadsheets.

## 2. Current Implementation

### 2.1 Sync Strategies & Mutation Coalescing
- Mutations to daily workout records (`addDailyRecordOptimistic`, `editDailyRecordOptimistic`, `deleteDailyRecordOptimistic`) commit to in-memory `WorkoutDbContext` and local `SharedPreferences` cache instantly with 0ms UI blocking.
- Background uploads to Google Drive Excel are debounced (`Duration(milliseconds: 1500)`) and serialized via `syncDailyRecordsToDriveInBackground()`. Rapid set additions coalesce into a single serialized Drive sync operation, preventing concurrent overlapping uploads and race conditions.
- Upload encoding operates on an isolated `WorkoutDbContext` instance (`uploadContext`) so the singleton `dbContext` state is never temporarily mutated with historical records during async network I/O.

### 2.2 Local Caching and Purge Policies
The local cache for daily records differentiates between transactional operations and analytical queries:
- `getDailyRecords()` reads today's records and enforces a purge policy, deleting historical (non-today) records from cache memory. This is used for today's active workout session.
- `getWeeklyDailyRecords()` is a read-only method that safely reads the raw `SharedPreferences` cache for the entire Monday–Sunday window without triggering the purge policy. This correctly supports historical data displays like the weekly activity heatmap without wiping the cache.
- `loadRecentDailyRecordsFromBytes()` filters sheet rows without early termination to guard against out-of-order rows in manually edited workbooks.

## 3. Patterns & Conventions
- **Offline-First**: Reads from local cache; writes commit locally and sync asynchronously.
- **Debounced Upload Coalescing**: Consecutive mutations collapse into a single network sync after an idle threshold.
- **Serialized Work Queue**: Active sync runs complete before queued syncs execute with the latest snapshot.
- **Cache Isolation**: Separating mutating read methods (purge) from read-only analytical methods.
