## 1. Overview
State management utilizes Flutter's native `ChangeNotifier` ViewModels, `ValueListenable` / `ValueNotifier` for reactive observables, and `StatefulWidget` for purely local ephemeral UI state.

## 2. Current Implementation
### 2.1 View Models and Notifiers
- **`TodaysWorkoutLogViewModel`**: Extends `ChangeNotifier`, providing cache-first instant loading, PR (Personal Record) peak 1RM detection, previous set memory lookups (`getLastRecordedSet`), optimistic save/edit/delete/restore operations, and exposes `syncStateListenable` from `WorkoutRepository`.
- **`ExerciseStatisticsViewModel`**: Extends `ChangeNotifier`, computing strength trend points, timeframe filters, peak performance, and caching computed statistics by exercise and days to eliminate redundant calculations.
- **`ValueListenable` / `ValueNotifier`**: Used for cross-cutting synchronization status (`SyncState`), powering `CompactSyncButton` without rebuilding entire widget trees.

## 3. Patterns & Conventions
- **MVVM Pattern**: ViewModels manage UI presentation logic, exposing reactive getters and notifying listeners.
- **Cache-First Instant Rendering**: ViewModels immediately render cached in-memory/SharedPreferences state before triggering asynchronous background refreshes.
- **ValueListenable**: Used for fine-grained reactivity on sync status badges and progress indicators.
