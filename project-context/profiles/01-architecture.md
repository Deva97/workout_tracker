## 1. Overview
The project follows Clean Architecture principles, separated into Domain, Data, and UI layers. It relies heavily on a custom Excel ORM for data persistence over Google Drive.

## 2. Current Implementation
### 2.1 Clean Architecture Implementation
The application segregates responsibilities cleanly. `lib/domain/` houses business rules (models, repositories interfaces, use cases). `lib/data/` contains repository implementations and services, particularly a custom ORM in `lib/data/orm/` for Google Sheets. `lib/ui/` is split into `core/` (shared widgets, theme) and `features/` (feature-based organization with views and view models).

### 2.2 Repository Pattern
The repository pattern isolates data access concerns effectively. A strong example is the `WorkoutRepository` interface, which defines distinct data access strategies: `getWeeklyDailyRecords()` serves as a read-only query method that bypasses the underlying `GoogleDriveService` purge policy, while other methods handle active data mutation. This abstracts the cache management details away from the domain layer.

## 3. Patterns & Conventions
- **Clean Architecture**: Domain, Data, and UI separation.
- **Repository Pattern**: Abstract interfaces in Domain, implemented in Data layer.
